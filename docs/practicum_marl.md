# Практическая работа: мультиагентное обучение с подкреплением в FlySwarm

## Тема и цель

Практическая знакомит с многоагентной средой, командной наградой, базовым случайным контроллером и обучением PPO. Студент учится формулировать гипотезу, запускать воспроизводимые эксперименты, читать кривую обучения и сравнивать политику на независимых эпизодах.

## Модель и инструменты

Среда `FlySwarmParallelEnv` реализует API PettingZoo Parallel: все 16 машин получают действие одновременно. В стандартной конфигурации сражаются две команды по восемь машин. Python является источником всех аналитических состояний, наград, повреждений и исхода. Godot Viewer воспроизводит записанные состояния и события и не пересчитывает результат боя. Модель аналитическая: это не баллистический и не броневой симулятор из обычного режима Godot. Эффект попадания разрешён только при достаточной дальности и наведении; точная зона попадания в аналитическом backend неизвестна.

Студенческая лаборатория использует одну общую среду 8×8 для Random, собственного агента и обеих PPO-политик. Вторая команда управляется фиксированной контрольной политикой. В диагностическом backend могут оставаться другие сценарии, но интерфейс практической их не назначает, а результаты из разных конфигураций не смешиваются. PPO обучает внешнюю политику управления, а не MaleCNS connectome. В наблюдениях MaleCNS-входы могут быть нулевыми, если они недоступны; они не синтезируются.

## Установка и запуск Python CLI

Для аналитической части не нужны Godot и MaleCNS. Нужны Python 3.11 и зависимости проекта. Создайте окружение и установите зависимости из корня репозитория:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
.venv\Scripts\python.exe -m flyswarm.marl.cli baseline --episodes 3 --seed 101
```

На macOS или Linux используйте `.venv/bin/python` и `PYTHONPATH=src`; команды `baseline`, `train`, `evaluate` и `compare` одинаковы на всех трёх системах. Окружение `venv` создаётся отдельно для каждой ОС. 3D viewer проверяется и поставляется в основном приложении macOS; Windows GUI и MaleCNS остаются неподтверждёнными до ручного теста на физическом Windows-компьютере. Автоматизированный Windows workflow проверяет экспорт Godot, установщик, запуск приложения без окна и MARL Python backend.

## Наблюдения и действия

Наблюдение каждого агента — документированный NumPy-массив из 30 чисел: шесть доступных нейронных признаков, скорость, перезарядка, здоровье, состояние машины, текущий угол башни и УВН, положение ближайшей точки, владение и прогресс захвата, билеты команд, относительный угол и дальность ближайшего видимого противника, затем восемь инженерных признаков класса, страны и тактического профиля. Эти признаки являются настройками эксперимента, а не биологическими свойствами MaleCNS. Скрытое состояние соперника в Python-код не передаётся.

Действие — шесть непрерывных величин в диапазоне [-1, 1]: тяга, тормоз, поворот корпуса, поворот башни, УВН и огонь. Динамика корпуса, башни и орудия ограничена скоростями выбранной машины. Выстрел наносит аналитический урон только при цели в дальности и достаточном наведении. Воспроизведение отображает фактические координаты, значения здоровья, награды, зоны и события Python.

## Награда

Компоненты по умолчанию: прогресс цели 0.02, захват 3, нейтрализация 1, урон 0.01, уничтожение противника 4, потеря своей машины -4, преимущество по билетам 0.01, победа 10, поражение -10 и ролевое shaping 0.25. Значения сохраняются в manifest каждого опыта. Награда одного шага контролируемой команды равна сумме наград восьми её агентов; итоговая командная награда — сумма этой величины по шагам эпизода. При сравнении Random и PPO сохраняются одинаковые тестовые seed, состав, ограничение эпизода, награды и фиксированный соперник. После расхождения действий одинаковый seed не гарантирует одинаковую траекторию.

## Запуск Python-практической

Команды выполняются из корня проекта после `python -m pip install -r requirements.txt`. В macOS/Linux используйте `.venv/bin/python`, в Windows — `.venv\\Scripts\\python.exe`; сначала установите зависимости проекта. Вызовы ниже не требуют Godot, MaleCNS или dataset:

```sh
PYTHONPATH=src .venv/bin/python -m flyswarm.marl.cli baseline --episodes 5 --seed 101
PYTHONPATH=src .venv/bin/python -m flyswarm.marl.cli train --steps 10000 --seed 7
PYTHONPATH=src .venv/bin/python -m flyswarm.marl.cli evaluate results/raw/marl/<training-id>/checkpoint/ppo_team.zip --episodes 5 --seed 1001
PYTHONPATH=src .venv/bin/python -m flyswarm.marl.cli compare results/raw/marl/<training-id>/checkpoint/ppo_team.zip --episodes 5 --seed 1001
```

Каждый запуск создаёт новый каталог в `results/raw/marl/` с конфигурацией, manifest, таблицами, summary, графиками, checkpoint (для обучения) и JSONL replay. Эти результаты исключены из публикации исходников. `progress.json` содержит ход обучения. Результаты нельзя сравнивать, если различаются тестовые условия. Evaluation seeds должны быть отделены от seed обучения.

## Анализ и отчёт

Используйте `training.csv` и `plots/learning_curve.png` для динамики награды на обучении. Используйте `comparison.csv`, `summary.json` и `plots/random_vs_ppo.png` для независимого paired evaluation. Отчёт должен содержать вопрос и гипотезу, версию/commit, параметры, seeds, число шагов и эпизодов, среднюю командную награду, победы, захваты, потери, график и ограничения модели. Зафиксируйте отрицательный или неоднозначный результат без подмены тестовых метрик обучающими.

Визуальный replay помогает исследовать поведение, но не заменяет численный анализ: зрелищный эпизод не оценивает разброс результатов. Обученная политика не обязана побеждать случайную на коротком запуске. Нужны несколько независимых test seeds и анализ метрик. Godot replay визуализирует сериализованный результат аналитической среды; его собственные физика, броня и баллистика доступны в отдельных игровых режимах и не участвуют в этих числах.

## Уровни и вопросы для защиты

Задание и критерии поведения определяет преподаватель. FlySwarm не выбирает за студента алгоритм, тактику или функцию награды. Студент может использовать `act(observation, context=None)` для индивидуальной политики либо `act_team(observations, contexts)` для согласованного управления; при наличии `act_team()` он имеет приоритет. `reset(seed)` очищает внутреннее состояние перед эпизодом. PPO — отдельная обучаемая политика и не меняет `agent.py`.

Для защиты объясните: чем Parallel API отличается от последовательного шага; почему команда агрегирует восемь наград; что означают observation/action spaces; почему PPO может не улучшить метрику; зачем фиксировать seed; почему сравнение обучающих reward с тестовыми некорректно; какие состояния решает Python и что только отображает Godot; почему PPO не обучает MaleCNS.

Полноценный интерактивный GUI-прогон и 3D Viewer относятся к приложению FlySwarm. Наличие Python CLI само по себе не означает, что GUI-практическая прошла визуальную валидацию.

## Собственные программы студента

Во вкладке Python доступны `agent.py` и `reward.py`, импорт/сохранение, проверка, запуск собственной стратегии, обе PPO-политики, сравнение четырёх вариантов и экспорт практической в ZIP. Полный контракт и значения компонентов награды приведены в [Python API MARL](marl_python_api.md). Пользовательская награда может принимать только `components` либо дополнительно публичные observation, action, next_observation и context. Она пакетно вычисляется для синхронного шага и действительно используется PPO; независимое сравнение всегда использует одну стандартную метрику.

Для parameter-sharing PPO один синхронный шаг среды даёт восемь переходов отдельных машин. Progress разделяет эти переходы, шаги мира, завершённые эпизоды и обновления PPO, чтобы показатель 200 000 переходов не выглядел как 200 000 шагов боя.

Пользовательский Python запускается с правами текущей учётной записи. Отдельный процесс, тайм-аут стратегии и кнопка остановки не создают безопасную песочницу. Запускайте только доверенный код. Результаты каждого запуска сохраняются отдельно вместе с копиями кода и хешами; ZIP экспортирует только существующие материалы практической.
